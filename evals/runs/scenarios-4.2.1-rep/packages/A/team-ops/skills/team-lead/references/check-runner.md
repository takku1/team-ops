# Optional local check runner

Load only when running `check_runner.py`. [The script](../scripts/check_runner.py) uses only Python's standard library and ships with this skill; invoke it by its installed path. It launches argument arrays without a shell and writes logs plus a result ledger to a scratch `--state-dir` **outside the checked workspace**. It does not dispatch agents, enforce write scopes, sandbox commands, provide distributed locks, or enforce token budgets.

```powershell
python <installed-skill>/scripts/check_runner.py --cwd <workspace> --state-dir <scratch-outside-workspace> --input src --input tests --input pyproject.toml --input uv.lock --identity <toolchain-and-dependency-id> -- python -m pytest
```

- **Inputs:** pass every relevant file/directory explicitly, including instruction, config, lockfiles, and generated inputs that affect behavior. Directories include hidden/untracked files. Symlinks are rejected. Indirect tools and installed packages are not discovered: supply `--identity`. The executable is resolved and hashed (use the real binary when a Windows app-execution alias is unreadable); batch wrappers need an explicit shell executable. The inherited environment is hashed, never stored as plaintext.
- **Reuse:** default is fresh execution (`--fresh`, exclusive with `--reuse`). `--reuse` asserts the check is deterministic with complete inputs; matching concurrent requests then share one successful execution. Failures and stale results are never reused. Use `--fresh` for independent verification. Waiters have a bounded `--lock-timeout` (default 60 s).
- **Explain:** `--explain` with the same inputs and command reports eligibility without running. JSON `cache.reasons` names changed categories (inputs, input scope, command, executable, toolchain, environment, workspace, platform) or first run, corrupt records, missing logs, prior failure/unstable inputs, or explicit fresh. It compares against an exact record or the lane's latest run; it is not causal diagnosis and does not certify determinism. Volatile environment variables can cause conservative misses; do not drop environment inputs to raise hit rate. Schema 2 records do not match older ones.
- **Lanes:** one state directory is one serialized lane, fresh checks included. Use separate directories only for genuinely independent build resources. Locks release on process exit, but a parent crash can leave a child running: inspect the lane after an interrupted run. Network filesystems and multi-host execution need a real scheduler.
- **Results:** JSON includes input identity, command, exit code, log paths, reuse status, and input stability. Inputs changed during execution make the result stale and the runner exit nonzero, even if the command returned zero. Pre/post hashing misses change-and-restore races, so pause writers or snapshot. Keep generated outputs outside declared inputs.
- **Secrets:** after each run, secret-shaped spans (private keys, AWS/GitHub/`sk-` keys, bearer tokens, `password=`-style values) are redacted from logs and counted in `redactions`. This is best effort; logs can still contain secrets. Keep state private, redact before sharing, never commit it. Equivalent current CI provenance may be consumed directly instead.
