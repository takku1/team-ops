A successful review does not approve as-is: it verifies the package exists and is the intended one (AI-suggested names can be hallucinated or typosquatted), weighs maintenance, provenance, and transitive footprint, and checks that it actually fits the security need (HTML escaping for comments is better served by a well-established, maintained library or the framework's own escaping). It proposes concrete conditions or an alternative and ties claims to the stated facts. Fails if it approves outright.
