# Team Topologies

Use when work stalls between teams rather than inside them.

Prose: classify each team as stream-aligned, platform, enabling, or complicated-subsystem. Declare one interaction mode per pair: collaboration, X-as-a-service, or facilitation. Inverse-Conway move: shape teams to the desired architecture. Reduce cognitive load on stream-aligned teams.

Logic:
- require team list and architecture sketch exists
- classify type per team, declare mode per pair
- flag overloaded stream-aligned teams
- return topology map plus load risks
